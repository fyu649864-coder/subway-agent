## 四、分组划分后 train / val / test 的情绪类别分布

| 子集 | 行数 | group 数 | 覆盖类别数 | 类别分布 |
|------|------|---------|-----------|---------|
| 训练集 | 5720 | 101 | **57（全部）** | 庆幸179、平静170、着急170、疑惑165、厌恶163、焦急161、失望161、不满156、担心152、疲惫152、无语150、满意149、建议146、舒心145、不便144、平复144、压抑142、烦躁136、愤怒136、感激132、困惑132、无奈112、开心112、难受110、生气110、感动110、惊吓110、恼火110、懊恼110、理解109、认可106、…（其余 26 类各 52–56） |
| 验证集 | 233 | 6 | **仅 5 类** | 无奈71、认可66、愤怒38、烦躁29、满意29 |
| 测试集 | 226 | 5 | **仅 5 类** | **焦虑109**、困惑36、感激36、不满24、烦躁21 |

**严重问题**：
1. 验证集和测试集各自只覆盖 5/57 类，且两者类别几乎不重叠（仅共有「烦躁」）。
2. 测试集被「焦虑」单一 group 主导（109/226 ≈ **48%**）。**多数类基线（恒预测「焦虑」）即可达到 48% 准确率，而当前模型测试集 Accuracy 仅 16.4%，甚至低于多数类基线** —— 说明模型在未见 group 上几乎没有有效泛化。
3. macro-F1 在全部 57 类上计算，其中 52 类在测试集中根本不存在，recall=0、F1=0，直接把 macro-F1 拉到 0.0753。**macro-F1 在此划分下不是一个公平的指标**；weighted-F1（0.168）和 Accuracy（0.164）更能反映测试集上的真实表现。

## 五、是否存在某些情绪类别几乎全部集中在少数原始样本中

**是，且非常严重。** 31/57 类只有 1 个原始样本（即 1 个 group），这些类的全部 55–145 条增强行都来自同一句模板的改写。其余类别也高度集中：

- 「烦躁」7 个原始样本 → 186 行
- 「不满」7 个原始样本 → 180 行
- 「满意」6 个原始样本 → 178 行
- 「焦虑」仅 2 个原始样本 → 161 行（测试集 109 行焦虑全来自其中 1 个 group）

模型极易学到「模板文本 → 情绪」的捷径，而非可迁移的情绪语义；一旦测试集出现训练集未见的模板，即崩溃。

## 六、标签质量检查

- 无空标签、无重复文本（已去重）。
- 同 group 内情绪 100% 一致，未发现标签错位。
- 57 类粒度**极细**且语义大量重叠，例如：
  - 焦虑 / 焦急 / 着急 / 紧张 / 恐慌
  - 愤怒 / 恼火 / 生气 / 烦躁 / 不满 / 反感 / 厌恶
  - 感激 / 感动 / 暖心 / 欣慰 / 敬佩 / 认可 / 满意
  - 困惑 / 疑惑 / 不解
  - 疲惫 / 难受 / 不适 / 压抑
  
  细粒度 + 单模板，导致跨 group 时同类表述差异大、异类表述反而相似，进一步加剧泛化困难。
- 另外数据集含 `情绪类别` 字段（正面/中性/负面），112 条原始样本均有值，但**增强行该字段为空**，若要做粗粒度 3 分类需先为增强行回填（可用其所属 group 的原始行极性）。

## 七、F1=0.0753 的原因归因（按重要性排序）

| 候选原因 | 是否成立 | 说明 |
|---------|---------|------|
| **A. 原始数据太少** | ✅ **主因（根本）** | 独立原始样本仅 112 条；31/57 类只有 1 条原始样本。模型本质上只见过约 100 个不同的语义模板。 |
| **B. 类别严重不平衡 + 粒度过细** | ✅ **主因** | 57 类对 112 条原始样本，平均每类不足 2 条原始样本；31 类单样本。分组划分后 val/test 只能覆盖 5 类。 |
| **C. 测试集指标计算方式** | ✅ **直接原因（解释 0.0753 这个数字）** | macro-F1 在 57 类上平均，52 类在测试集不存在 → 贡献 0。改用「测试集出现类上的 macro-F1」或 weighted-F1（0.168）会更真实，但即便如此 Accuracy 仍只有 16.4%，低于多数类基线 48%。 |
| **D. 分组方式有问题** | ❌ 不成立 | group_id 推断 100% 正确（原始行匹配率 100%，增强行情景/情绪一致率 100%，无跨多标签/多场景 group，跨子集泄漏 group 数 = 0）。 |
| **E. 数据增强方式有问题** | ⚠️ 部分成立 | 增强本身质量没问题（同场景同情绪），但**改写增强无法创造新的独立语义样本**，反而放大了模板泄漏风险。随机划分的 0.9968 就是改写泄漏的证据。 |
| **F. 标签质量问题** | ⚠️ 次要 | 标签本身无错配，但 57 类粒度过细、语义重叠，增加了任务难度。 |
| **G. 模型训练参数问题** | ⚠️ 次要 | 存在过拟合（train_loss 0.50 vs val_loss 4.3），但即使调参也无法突破「112 条独立样本」的数据墙；不是主因。 |

**一句话结论：F1=0.0753 ≈ 数据问题（A+B+C），不是代码/划分 bug。** 0.0753 这个具体数值主要由 C（macro 在 57 类上平均、测试集仅 5 类）造成；真实泛化差则由 A+B 决定。

## 八、下一步最推荐的解决方案（按优先级）

1. **【根本】补充真实独立样本**：收集数千条**未参与增强**的真实乘客原话，覆盖主要场景与情绪。这是唯一能从根本上提升泛化能力的手段。在此之前，任何细粒度情绪分类模型都不可信。
2. **【高】标签归并**：将 57 类按语义合并为 **15–20 类**（如 焦虑族、愤怒族、感激族、困惑族、疲惫族等），降低任务难度，缓解单样本类别问题。归并后重新分组划分。
3. **【高】修正评估口径**：
   - 报告 **weighted-F1 / Accuracy** 为主，macro-F1 为辅；
   - 或在「测试集实际出现的类别子集」上计算 macro-F1，避免 52 个空类拉低指标；
   - 始终报告**多数类基线**（当前测试集为 48%），模型必须显著超过它才算有效。
4. **【中】先用粗粒度验证流程**：用 `情绪类别`（正面/中性/负面，需为增强行回填）做 3 分类，验证分组划分 + 训练 + 评估全流程在「无泄漏」下是否可学习，再上细粒度。
5. **【中】降低过拟合**：增大 dropout、减小 epoch、加重 weight decay、降低学习率；或换 RoBERTa-wwm。但这是次要矛盾。
6. **暂缓工程接入**：在泛化能力改善前，不替换 `PerceptionService` 的 mock 规则。
