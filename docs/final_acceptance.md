# 最终验收报告

## 一、启动方式

后端（在 `backend/` 目录）：
```
python -m uvicorn app.main:app --port 8000
```
前端（在 `frontend/` 目录）：
```
python -m http.server 8080 --bind 127.0.0.1
```
浏览器打开 http://127.0.0.1:8080/ 。前端默认请求 `http://127.0.0.1:8000`，可用 `?api=http://host:port` 覆盖。
建议先启动后端再打开前端；即便前端先打开，健康检查会自动重试。

## 二、关于 `/health` 偶发连接失败的结论与修复

- 原因确认：**启动时序导致**。前端加载时若后端尚未就绪，单次 `/health` 失败会立即把「发送」按钮禁用，且原逻辑要等 15 秒才再次轮询，造成「按钮被锁死、看似连接失败」的假象。`/health` 本身为轻量接口，不加载模型，无服务端性能问题。
- 修复（`frontend/app.js`）：`checkHealth` 增加最多 3 次、间隔 800ms 的重试；仅在重试耗尽后才标记「后端未连接」并禁用按钮。后端启动后会在数秒内自动恢复为「后端已连接」。本次修改不涉及后端业务逻辑。

## 四、已知限制

- 历史记录仅存于浏览器 localStorage，清缓存/换设备即丢失，无服务端同步。
- CORS 为本地开发配置（默认允许 127.0.0.1:8080 / localhost:8080），生产部署需通过 `METRO_CORS_ALLOW_ORIGINS` 收紧。
- 回复为本地模板，未做生成式个性化；实时路况与具体线路以官方渠道为准。
- 情绪模型为 CPU 推理、进程内懒加载，首次请求有加载耗时。
- 「后端不可用」场景未做真实断电回归，仅逻辑覆盖。
- 存在 starlette/httpx 的弃用 warning，不影响功能。
