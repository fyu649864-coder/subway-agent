## 四、模型方案对比与推荐

针对项目目标（情绪识别 + 事件识别），对四种方案进行评估：

| 方案 | 适用性 | 理由 |
|------|--------|------|
| ① 单模型多分类（仅情绪 57 类） | ⚠️ 部分适用 | 能完成情绪分类，但浪费了 `场景` 标签，无法输出事件识别结果 |
| ② 情绪模型 + 事件模型（两个独立分类器） | ✅ **推荐** | 两个标签均全量覆盖、独立可用；解耦清晰，易于单独迭代；工程复杂度低 |
| ③ 情绪分类 + 强度预测 | ❌ 不适用 | 数据集**无强度标签**，无法训练回归头 |
| ④ 多任务模型（共享编码器 + 情绪头 + 事件头） | ✅ 可选（进阶） | 数据上完全可行（文本→情绪+场景），参数效率高；但实现与调参复杂度高于方案②，建议作为二期优化 |

### 推荐方案：**方案② 为主，方案④ 为进阶目标**

- **当前阶段（第二阶段→第三阶段）**：采用**两个独立的中文预训练分类模型**——
  - **情绪分类器**：输入 `乘客说的话` → 输出 `情绪`（57 类，或归并后的类别）。
  - **事件分类器**：输入 `乘客说的话` → 输出 `场景`（20 类）。
  - 骨干网络推荐：`bert-base-chinese` 或 `hfl/chinese-roberta-wwm-ext`。
- **后续优化**：在两个单任务模型稳定后，可升级为**共享编码器的多任务模型**（方案④），以降低推理成本并利用任务间关联。
- **强度预测**：当前数据不支持，建议**暂缓**；如确需强度输出，可由情绪类别 + 规则启发式给出（如 愤怒/恐慌→高强度），或后续补充标注。

## 五、发现的主要问题与处理建议

| 问题 | 严重度 | 建议 |
|------|--------|------|
| `情绪类别` 仅 112 行有值，增强数据缺失 | 中 | 如需极性分类，需补全：可用「情绪→极性」映射规则批量生成，存为新文件，**不覆盖原始数据** |
| `序号` 大部分缺失 | 低 | 不影响训练，可忽略或在处理时剔除 |
| 情绪标签 57 类，存在语义重叠（焦虑/焦急/着急 等） | 中 | 建议训练前做**标签归并**（如合并为 15–25 类），降低分类难度、提升小样本类的鲁棒性；归并映射表另存，不改动原表 |
| `场景` 存在中度不均衡（12.7:1） | 中 | 训练时对 `宠物气味` 等小类使用 class weight 或过采样；划分数据集时按 `场景` 分层抽样 |
| 文本极短（最长 34 字） | 信息 | 利好：max_length=64 足够，推理快；注意：短句上下文少，需依赖预训练语义 |
| 无强度标签 | 高（若需强度） | 本数据集无法支持强度回归，建议后续补充标注或采用启发式规则 |

> 以上均为**建议**，原始 `augmented_metro.xlsx` 不做任何修改。若需生成处理后的数据，必须另存为新文件（如 `data/processed/metro_clean.csv`）。
